# SecretApp End-to-End Testing

Full-flow verification of the app: access gate → create invite → invitee responds → manage page shows the answer → notification email sends. Run the local pass after any change; run the production pass after deploying.

## Prerequisites

- `.env` at the repo root with `DATABASE_URL` (local Postgres), `ACCESS_CODES`, `GOOGLE_GENERATIVE_AI_API_KEY`, and `BREVO_API_KEY` + `BREVO_SENDER_EMAIL`. See `.env.example`.
- Local Postgres running, schema up to date: `npx prisma migrate dev`
- Pick a valid access code from `ACCESS_CODES` in `.env` (referred to as `$CODE` below). Never commit or log real codes.

## Local pass

Copy this checklist and track progress:

```
- [ ] 1. Lint + build
- [ ] 2. Start the production server locally
- [ ] 3. API smoke tests
- [ ] 4. Browser flow test
- [ ] 5. Check server logs for errors
```

**1. Lint + build** (the build runs `prisma generate` first):

```bash
npx eslint src --max-warnings=0 && npm run build
```

**2. Start the server** in a background terminal and wait for "Ready":

```bash
npm run start   # serves on http://localhost:3000
```

Kill any previously running instance first, or the port will be taken.

**3. API smoke tests** — expected status in comments:

```bash
# Access gate: valid code → 200, garbage → 401
curl -s -w '%{http_code}' -X POST localhost:3000/api/access \
  -H 'Content-Type: application/json' -d '{"accessCode":"'$CODE'"}'

# Create invite → 201 with {slug, secret}; without a valid accessCode → 401
curl -s -X POST localhost:3000/api/invites \
  -H 'Content-Type: application/json' \
  -d '{"accessCode":"'$CODE'","fromName":"Test","toName":"E2E","message":"hi!","theme":"blush","location":"Test Cafe, SF","notifyEmail":"","dateOptions":[{"label":"dinner","iso":"2030-01-10T03:00:00.000Z"}]}'

# Respond (use slug from previous step) → 201
curl -s -X POST localhost:3000/api/invites/$SLUG/response \
  -H 'Content-Type: application/json' \
  -d '{"accepted":true,"selectedOptionIds":[],"proposedTimes":["2030-01-11T03:00:00.000Z"],"note":"e2e test"}'

# AI suggestion (needs GOOGLE_GENERATIVE_AI_API_KEY) → 200 with {message}
curl -s -X POST localhost:3000/api/suggest-message \
  -H 'Content-Type: application/json' \
  -d '{"accessCode":"'$CODE'","fromName":"Test","toName":"E2E","vibe":"sweet","idea":"ramen"}'
```

Note: `selectedOptionIds` must reference option ids generated by the server (fetch them from the DB or pass `[]` and use `proposedTimes`).

**4. Browser flow test** — use the in-IDE browser:

1. `/new` → the access-code gate card appears (not the form). Wrong code shows an error; `$CODE` unlocks the form. On reload it auto-unlocks (code is kept in localStorage).
2. Fill the form: names, message, optional location, then the date picker — tap a day chip, a time chip, then "+ Add"; a pill appears and "Create my invite" enables (it is disabled while there are zero date pills).
3. Submit → redirected to `/manage/<secret>?created=1` with the share link.
4. Open `/i/<slug>` → envelope → card (location + Google/Apple Maps links if set) → "Yes!" → pick/propose times → send. Confetti and "It's a date!" with add-to-calendar buttons.
5. Back on `/manage/<secret>` → the answer, selected/proposed times, and calendar buttons render. If a location was set, verify the Google Calendar `href` contains `location=`.

**5. Check logs** in the server terminal for Brevo failures or stack traces:

```bash
rg -i 'brevo|error' <server output>
```

If `notifyEmail` was set on the invite, a response should log no Brevo errors (silence = the email was accepted).

## Production pass (after deploy)

Production URL: `https://secretapp-rust.vercel.app` (Vercel project `secretapp`, auto-deploys from `main`).

1. **Schema changes**: run `npx prisma migrate deploy` against the Neon `DATABASE_URL` **before** the code deploy goes live (`npx vercel env pull` to obtain it; delete the pulled file afterwards).
2. Wait for the deploy: `npx vercel ls` → newest deployment shows "Ready" (~30–90s after push).
3. Re-run the API smoke tests above against the production URL.
4. Check runtime logs: `npx vercel logs secretapp-rust.vercel.app` and grep for `Brevo`/`error`.
5. Test invites created in production are real DB rows — use obvious test names (e.g. "E2E Test") so they can be cleaned up later.

## Known gotchas

- Restart `npm run start` after every rebuild; it serves the `.next` from startup.
- Do not create `.env.local` from `vercel env pull` in the repo root — it overrides `.env` and points local dev at the production Neon database.
- Brevo rejects API calls from unrecognized IPs if the account's IP restriction is enabled; production (Vercel) requires it to be off.
- A stale client bundle across a deploy can break form interactivity (symptom: filled form but disabled submit button); hard-refresh before diagnosing further.
